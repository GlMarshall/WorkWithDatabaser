# Rnd — Console CRUD Application (Enterprise Architecture)

## 📖 О проекте

**Rnd** — это консольное приложение для управления данными, построенное с применением профессиональных паттернов проектирования и лучших практик .NET. 

Проект демонстрирует навыки разработки масштабируемых приложений: от работы с базой данных через EF Core до интерактивного интерфейса командной строки с использованием паттерна Command.

## 🚀 Ключевые возможности

*   **Полный CRUD** для сущностей `Person`, `Order` и `Category`.
*   **Связанные сущности** (One-to-Many) с каскадной логикой.
*   **Интерактивный CLI-интерфейс** с поддержкой команд и алиасов.
*   **Профессиональное логирование** в консоль и файл.
*   **Пагинация** и фильтрация данных на уровне SQL-запросов.
*   **Мягкое удаление** (Soft Delete) через глобальные фильтры EF Core.

## 🛠️ Технологический стек

*   **Платформа:** .NET 10 (C#)
*   **База данных:** SQLite
*   **ORM:** Entity Framework Core 8.0
*   **Маппинг:** AutoMapper (с использованием `ProjectTo`)
*   **Логирование:** Serilog (Console + File Sinks)
*   **Паттерны:** Command, Repository, Service Layer, DTO, Dependency Injection (Manual)

## 🏗️ Архитектура и примененные практики

Проект построен с разделением ответственности (Separation of Concerns) и следует принципам SOLID.

### 1. Паттерн Command (Интерактивный интерфейс)
*   Каждая команда (например, `add-person`, `list-orders`) инкапсулирована в отдельный класс, реализующий `ICommand`.
*   **CommandFactory** используется для динамической регистрации и поиска команд (регистронезависимый поиск).
*   **CommandParser** поддерживает парсинг аргументов с пробелами (заключенных в кавычки).

### 2. Паттерн Repository (Слой доступа к данным)
*   Реализован обобщенный `Repository<T>`, абстрагирующий работу с `DbContext`.
*   Использование `GetQueryable()` для построения сложных LINQ-запросов.
*   Применение `AsNoTracking()` для оптимизации запросов только на чтение.

### 3. Service Layer (Бизнес-логика)
*   Выделен слой сервисов (`PersonService`, `OrderService`, `CategoryService`), который содержит бизнес-логику и маппинг.
*   Внедрение интерфейсов (`IPersonService`, `IOrderService`) для слабой связанности кода.

### 4. Работа с данными (EF Core)
*   **Code-First подход** с использованием миграций (`Migrations`).
*   **Fluent API** для конфигурации сущностей (`IEntityTypeConfiguration`).
*   **Глобальные фильтры** (`HasQueryFilter`) для реализации Soft Delete (`IsDeleted`).
*   **SeedData** для автоматического заполнения базы тестовыми данными.
*   Использование `Include` и `ProjectTo` для оптимизации связанных запросов.

### 5. DTO и AutoMapper
*   Четкое разделение сущностей БД (`Models`) и объектов передачи данных (`DTOs`).
*   Использование **AutoMapper** для автоматизации маппинга.
*   Применение `ProjectTo` для трансляции маппинга прямо в SQL-запрос (предотвращение N+1 проблемы).

### 6. Логирование и Обработка ошибок
*   Настроен **Serilog** с ротацией файлов по дням и ограничением размера.
*   Логирование всех ключевых действий (создание, удаление, ошибки).
*   Обработка исключений на уровне команд с возвратом структурированного `CommandResult`.
